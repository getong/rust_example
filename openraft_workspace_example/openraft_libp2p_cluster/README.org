* libp2p openraft multi-raft rocksdb

** usage

Raft groups: `users`, `orders`, `products`, `tasks`. Default group is `users`.
Use `group_id` in HTTP bodies, `--group` in CLI tools, or `?group=` on `/cluster`.

Five-node local runs use the legacy =./script/run-5nodes.sh= launcher and enable
=console-subscriber= for tokio-console. Each node binds a different console port
to avoid conflicts:

#+begin_src shell
./script/run-5nodes.sh

tokio-console http://127.0.0.1:6669 # node1
tokio-console http://127.0.0.1:6670 # node2
tokio-console http://127.0.0.1:6671 # node3
tokio-console http://127.0.0.1:6672 # node4
tokio-console http://127.0.0.1:6673 # node5
#+end_src

Override the defaults with =NODE1_TOKIO_CONSOLE_BIND=,
=NODE2_TOKIO_CONSOLE_BIND=, =NODE3_TOKIO_CONSOLE_BIND=,
=NODE4_TOKIO_CONSOLE_BIND=, or =NODE5_TOKIO_CONSOLE_BIND= when needed.

#+begin_src shell
# set (default group: users)
curl -X POST http://127.0.0.1:3001/write \
-H 'content-type: application/json' \
-d '{"key":"user:1","value":"Alice"}'

# set into orders group
curl -X POST http://127.0.0.1:3001/write \
-H 'content-type: application/json' \
-d '{"group_id":"orders","key":"order:1001","value":"pending"}'

# update products group
curl -X POST http://127.0.0.1:3002/update \
-H 'content-type: application/json' \
-d '{"group_id":"products","key":"product:A","value":"Widget"}'

# delete from users group
curl -X POST http://127.0.0.1:3002/delete \
-H 'content-type: application/json' \
-d '{"group_id":"users","key":"user:1"}'

# get cluster info (default group)
curl http://127.0.0.1:3001/cluster

# get cluster info for orders group
curl "http://127.0.0.1:3001/cluster?group=orders"

# list OpenRaft members for a group
curl http://127.0.0.1:3001/openraft/nodes
curl "http://127.0.0.1:3001/openraft/nodes?group=tasks"

# list libp2p known peers and their OpenRaft role, when any
curl http://127.0.0.1:3001/libp2p/nodes
curl "http://127.0.0.1:3001/libp2p/nodes?group=tasks"

# full libp2p stack info: identity/ports, live listeners and connections,
# request-response protocols (raft/kv/sqlite-sync), kademlia mode
# (Server on control, Client on workers) and routing table size, gossipsub
# topics with mesh/subscriber counts, ping/mdns config, address book
curl http://127.0.0.1:3001/libp2p/info

# chat
curl -X POST http://127.0.0.1:3001/chat \
  -H 'content-type: application/json' \
  -d '{"text":"hello from http","from":"node1"}'

# publish this node's latest OpenRaft snapshot through libp2p gossipsub
# partial messages; receivers install it through OpenRaft APIs
curl -X POST http://127.0.0.1:3001/sync/snapshot \
  -H 'content-type: application/json' \
  -d '{"group_id":"users"}'

# enqueue an email task backed by the raft-native queue
curl -X POST http://127.0.0.1:3001/tasks/email \
  -H 'content-type: application/json' \
  -d '{"to":"test@example.com"}'

# list registered external workers and task state
curl http://127.0.0.1:3001/tasks/workers
curl http://127.0.0.1:3001/tasks

# queue health metrics: status counts, retries, oldest due-task age,
# worker liveness
curl http://127.0.0.1:3001/tasks/metrics

# safely remove an OpenRaft control node before shutting that node down
# send this to the current leader's HTTP port; omit group_id to remove from all groups
curl -X POST http://127.0.0.1:3001/openraft/membership/remove \
  -H 'content-type: application/json' \
  -d '{"node_id":"<node-id-to-remove>"}'

# or remove from a single raft group
curl -X POST http://127.0.0.1:3001/openraft/membership/remove \
  -H 'content-type: application/json' \
  -d '{"group_id":"users","node_id":"<node-id-to-remove>"}'
#+end_src

** tasks (raft-native queue)

Nodes start as libp2p workers by default. The node whose =--id= matches the
configured =--bootstrap-node= id creates the initial OpenRaft cluster. Other
nodes dial =--bootstrap-node= and ask the current OpenRaft leader to join;
automatic startup join stops when the control membership reaches
=--max-control-nodes=. The binary default is 3, while the local five-node
launcher sets ~MAX_CONTROL_NODES=5~ and passes =--max-control-nodes 5=. Nodes
accepted into OpenRaft membership promote to control nodes, and later nodes stay
as workers.

Tasks are DOMAIN COMMANDS in the =tasks= raft group's log (octopii-style):
=TaskEnqueue= / =TaskAssign= / =TaskClaim= / =TaskDone= / =TaskFail= /
=TaskRequeue= / =WorkerLease= are applied atomically by the state machine,
which maintains the task record (=task:rec:<id>=), the queued/assigned
secondary indexes (=task:idx:queued:<run_at>:<id>=,
=task:idx:assigned:<node>:<id>=), the idempotency table and worker leases
(=task:worker:<node>=) in one RocksDB write batch. Execution NEVER happens in
=apply()=: the leader's scheduler assigns due tasks to leased workers (and
publishes a gossip wake-up), the worker claims atomically via a =TaskClaim=
command, runs the side effect locally exactly once, and acks with
=TaskDone=/=TaskFail= (failed tasks re-queue with exponential backoff, up to
3 attempts). Workers and worker-mode HTTP frontends reach the control plane
through a tarpc =TaskRpc= service carried over the libp2p request-response
protocol =/openraft/task/1=.

Reliability knobs: each execution is bounded by a 30s timeout (a hung handler
counts as a failure and retries with backoff); the scheduler requeues tasks
stuck in Assigned/Running for over 60s on a live worker, and immediately when
the worker's lease dies; =/tasks/metrics= exposes status counts, retry totals
and worker liveness. For drills, recipients starting with =fail= simulate a
handler error and =slow= simulates a hang.

Start the five-node control plane:

#+begin_src shell
./script/run-5nodes.sh
#+end_src

Or start a 20-node cluster (5 control voters + 5 learners + 10 workers):

#+begin_src shell
./script/run-20nodes.sh

# tunables
TOTAL_NODES=20 CONTROL_NODES=5 LEARNER_NODES=5 ./script/run-20nodes.sh
KILL_STALE=1 ./script/run-20nodes.sh            # auto-clean stale node processes
VOTER_REPLACE_TIMEOUT_SECS=60 ./script/run-20nodes.sh
#+end_src

Crash-test a running 20-node cluster and bring the nodes back:

#+begin_src shell
# SIGKILL specific nodes (or `random <N>` for a random pick)
DB_ROOT=/tmp/openraft_libp2p_cluster_demo/<run-id> ./script/crash-nodes.sh 2 7
DB_ROOT=/tmp/openraft_libp2p_cluster_demo/<run-id> ./script/crash-nodes.sh random 3

# graceful stop instead: sends Ctrl-C (SIGINT) and waits for the node to leave
# kademlia, stop the libp2p swarm, and shut down its openraft groups cleanly
DB_ROOT=/tmp/openraft_libp2p_cluster_demo/<run-id> ./script/crash-nodes.sh graceful 2 7
DB_ROOT=/tmp/openraft_libp2p_cluster_demo/<run-id> ./script/crash-nodes.sh graceful random 3

# restart everything recorded in $DB_ROOT/crashed-nodes.txt (or pass indices)
DB_ROOT=/tmp/openraft_libp2p_cluster_demo/<run-id> ./script/restart-nodes.sh
#+end_src

A crashed voter restarted within =--voter-replace-timeout-secs= (default 300s)
keeps its voter seat; past the timeout the membership guard replaces it with a
learner and the returning node wipes its stale data and re-joins as a learner.

Start one or more external workers after copying the printed =DB_ROOT=:

#+begin_src shell
DB_ROOT=/tmp/openraft_libp2p_cluster_demo/<run-id> WORKER_INDEX=1 ./script/run-worker.sh
DB_ROOT=/tmp/openraft_libp2p_cluster_demo/<run-id> WORKER_INDEX=2 ./script/run-worker.sh
#+end_src

Or fetch the current control-plane information from =/cluster= and start four
workers at once:

#+begin_src shell
DB_ROOT=/tmp/openraft_libp2p_cluster_demo/<run-id> ./script/join-4workers.sh

# optional overrides
CLUSTER_HTTP=http://127.0.0.1:3002/cluster WORKER_COUNT=4 \
  DB_ROOT=/tmp/openraft_libp2p_cluster_demo/<run-id> ./script/join-4workers.sh
#+end_src

Worker libp2p listeners bind to =/ip4/0.0.0.0/tcp/<port>/wss= by default so
the LAN addresses advertised by mDNS are dialable by other peers. Worker HTTP
ports stay on =127.0.0.1= by default.

Workers can also accept task submissions on their own HTTP ports; they forward
the writes to the control plane:

#+begin_src shell
curl -X POST http://127.0.0.1:3101/tasks/email \
  -H 'content-type: application/json' \
  -d '{"to":"worker-submit@example.com"}'
#+end_src

Promote a running worker into OpenRaft membership by submitting the request to
the current leader:

#+begin_src shell
curl -X POST http://127.0.0.1:3001/openraft/membership/add \
  -H 'content-type: application/json' \
  -d '{"node_id":"<worker-peer-id>","addr":"/ip4/127.0.0.1/tcp/4101/wss/p2p/<worker-peer-id>"}'
#+end_src

** cli examples

#+begin_src shell
# write into users group
cargo run -p openraft_libp2p_cluster --bin olpc-kv -- \
  --addr /ip4/127.0.0.1/tcp/4001/p2p/<peerid1> \
  --group users \
  set --key user:2 --value Bob

# read from orders group
cargo run -p openraft_libp2p_cluster --bin olpc-kv -- \
  --addr /ip4/127.0.0.1/tcp/4001/p2p/<peerid1> \
  --group orders \
  get --key order:1001

# query metrics for products group
cargo run -p openraft_libp2p_cluster --bin olpc-status -- \
  --addr /ip4/127.0.0.1/tcp/4001/p2p/<peerid1> \
  --group products
#+end_src

** websocket

This project enables a websocket transport alongside TCP and QUIC. Use /ws
multiaddrs for listen and peer addresses.

#+begin_src shell
# listen with websocket
cargo run -p openraft_libp2p_cluster --bin openraft_libp2p_cluster -- \
  --id <peerid1> \
  --listen /ip4/0.0.0.0/tcp/4001/ws \
  --http 0.0.0.0:3001 \
  --db /tmp/openraft-node1 \
  --bootstrap-node <peerid1>=/ip4/127.0.0.1/tcp/4001/ws/p2p/<peerid1> \
  --advertise /ip4/127.0.0.1/tcp/4001/ws/p2p/<peerid1>

# join through the bootstrap node
cargo run -p openraft_libp2p_cluster --bin openraft_libp2p_cluster -- \
  --id <peerid2> \
  --listen /ip4/0.0.0.0/tcp/4002/ws \
  --http 0.0.0.0:3002 \
  --db /tmp/openraft-node2 \
  --bootstrap-node <peerid1>=/ip4/127.0.0.1/tcp/4001/ws/p2p/<peerid1> \
  --advertise /ip4/127.0.0.1/tcp/4002/ws/p2p/<peerid2>

# use websocket address in the kv client
cargo run -p openraft_libp2p_cluster --bin olpc-kv -- \
  --addr /ip4/127.0.0.1/tcp/4001/ws/p2p/<peerid1> \
  --group users \
  get --key counter

# use websocket address in the status client
cargo run -p openraft_libp2p_cluster --bin olpc-status -- \
  --addr /ip4/127.0.0.1/tcp/4001/ws/p2p/<peerid1>
#+end_src

Websocket limits (optional):

#+begin_src shell
# limit websocket frame size and redirects
--ws-max-data-size 10485760 --ws-max-redirects 2
#+end_src

Secure websocket (wss):

#+begin_src shell
# generate a local self-signed cert (DER)
./script/generate_wss_certs.sh ./certs localhost 127.0.0.1

# listen with wss using the generated cert
cargo run -p openraft_libp2p_cluster --bin openraft_libp2p_cluster -- \
  --id <peerid1> \
  --listen /ip4/0.0.0.0/tcp/4001/wss \
  --http 0.0.0.0:3001 \
  --db /tmp/openraft-node1 \
  --ws-tls-key ./certs/private.der \
  --ws-tls-cert ./certs/fullchain.der

# trust the self-signed cert when dialing
cargo run -p openraft_libp2p_cluster --bin olpc-kv -- \
  --addr /ip4/127.0.0.1/tcp/4001/wss/p2p/<peerid1> \
  --group users \
  --ws-tls-cert ./certs/fullchain.der \
  get --key counter
#+end_src

Notes:
- Websocket addresses use /ws (plain websocket). Secure websocket (/wss or /tls/ws)
  is not configured by default.
- You can keep using /tcp and /udp/quic-v1; websocket is an additional transport.
