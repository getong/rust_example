#+title: Rust 闭包：捕获、取值与类型适配

本项目是可运行的闭包示例。执行：

#+begin_src shell
cargo run
cargo test
#+end_src

代码入口是 =src/main.rs=。示例使用断言验证行为，因此程序没有额外输出也是正常的。

* 1. 闭包里面的数据能不能取出来？

可以“通过闭包提供的接口取出”，但不能直接访问闭包环境中的字段。

#+begin_src rust
let name = String::from("Rust");
let greet = || format!("hello, {name}");
assert_eq!(greet(), "hello, Rust");
#+end_src

编译器会为闭包生成一个匿名、唯一的环境类型，其中包含 =name= 字段；这个字段不是用户可以命名或访问的公开字段。因此不存在类似 =greet.name= 的语法。

如果需要取出数据，应在设计闭包时显式提供方式：

- 直接返回数据：=fn make() -> (String, impl Fn() -> String)=；
- 返回一个读取闭包：闭包内部捕获数据，调用读取闭包得到副本或引用；
- 把状态放进 =Cell=、=RefCell=、=Mutex= 等，再让闭包读写共享状态；
- 如果数据本来就不应被闭包拥有，可以只捕获引用，并正确标注生命周期。

注意 =move= 会把捕获变量的所有权移入闭包。闭包被调用后，数据可能被消费掉；这也是 =FnOnce= 闭包只能调用一次的常见原因。

* 2. 闭包可以转换为另一个闭包类型吗？

不能直接把一个闭包强制转换为另一个匿名闭包类型。即使两个闭包的参数、返回值和代码完全一样，它们仍然是不同的匿名类型：

#+begin_src rust
let first = |x: i32| x + 1;
let second = |x: i32| x + 1;
// first 和 second 的具体类型不同，不能互相赋值。
#+end_src

常用做法是创建一个新闭包包住旧闭包：

#+begin_src rust
fn adapt<F>(function: F) -> impl Fn(i32) -> i32
where
    F: Fn(i32) -> i32,
{
    move |input| function(input)
}
#+end_src

这叫“适配”，不是改变旧闭包的匿名类型。=src/main.rs= 中的 =adapt_fn= 展示了完整代码。

* 3. 转成其他闭包表示形式

** 3.1 转成 =impl Fn=：静态分发

函数可以返回 =impl Fn(...)=。调用方不需要知道匿名类型，编译器仍然知道具体类型，通常没有动态分发成本：

#+begin_src rust
fn make_adder(value: i32) -> impl Fn(i32) -> i32 {
    move |input| input + value
}
#+end_src

限制是：一个函数的每个返回路径必须是同一个具体闭包类型。不能在不同分支直接返回两个不同闭包；需要统一成 =Box<dyn Fn>=，或使用枚举。

** 3.2 转成 =Box<dyn Fn>=：动态分发和可存储

#+begin_src rust
let function: Box<dyn Fn(i32) -> i32> = Box::new(|input| input * 2);
assert_eq!(function(3), 6);
#+end_src

这允许把不同具体闭包放进同一个变量、结构体或 =Vec=。通常要求捕获的数据满足 ='static=，因为 =Box= 默认可能独立于当前栈帧存在；若不需要拥有闭包，也可以写生命周期参数，例如 =Box<dyn Fn() + 'a>=。

** 3.3 转成函数指针 =fn(...)=：仅限不捕获环境

不捕获任何环境的闭包可以自动强制转换为函数指针：

#+begin_src rust
let square = |input: i32| input * input;
let pointer: fn(i32) -> i32 = square;
#+end_src

捕获变量的闭包不能转成函数指针：

#+begin_src rust
let factor = 2;
let multiply = |input: i32| input * factor;
// let pointer: fn(i32) -> i32 = multiply; // 编译错误
#+end_src

因为函数指针只有代码地址，没有保存捕获环境的空间。此时应使用 =impl Fn=、泛型 =F: Fn(...)= 或 =Box<dyn Fn(...)>=。

* 4. “不同范式”的闭包：=Fn=、=FnMut=、=FnOnce=

闭包实现哪一个 trait，由它如何使用捕获变量决定：

| Trait | 调用方式 | 常见捕获行为 |
|---|---|---|
| =Fn= | 可通过共享引用重复调用 | 只读借用捕获值 |
| =FnMut= | 需要可变借用，可重复调用 | 修改捕获值 |
| =FnOnce= | 消耗闭包，通常只能调用一次 | 把捕获值移动出去 |

它们是能力递减的层级：=Fn= 可以当作 =FnMut= 使用，=FnMut= 可以当作 =FnOnce= 使用；反过来不成立。

因此：

- 接收者只读调用时写 =F: Fn(...)=，约束最强但能力要求最高；
- 需要修改环境时写 =F: FnMut(...)=，调用函数内部通常要把参数声明为 =mut=；
- 需要消费环境时写 =F: FnOnce(...)=；
- 不要为了“统一类型”而把所有闭包都装进 trait object，泛型或 =impl Fn= 往往更简单、更高效。

* 5. 闭包的主要限制

1. **匿名类型不可命名。** 不能直接写出某个闭包的具体类型，也不能直接访问其捕获字段。
2. **同一函数不能直接返回两个不同闭包。** 用 =Box<dyn Fn>=、枚举或统一的函数指针解决。
3. **函数指针不能捕获。** =fn= 只有代码地址；需要环境时使用闭包 trait。
4. **生命周期不能逃逸。** 捕获局部变量引用的闭包不能返回到该局部变量失效之后；用 =move= 拥有数据，或返回带生命周期的闭包。
5. **所有权决定可调用次数。** 移出捕获值的闭包通常只能实现 =FnOnce=。
6. **自动 trait 由捕获字段决定。** 捕获了非 =Send= 或非 =Sync= 的值，闭包也不会自动成为 =Send= 或 =Sync=；跨线程传递时必须满足对应约束。
7. **闭包没有自动的 =Debug=、=Clone= 或相等比较实现。** 若需要这些能力，应把状态放在单独的结构体中，或自行设计包装类型。
8. **动态闭包有额外约束。** =dyn Fn= 使用虚调用并通常需要堆分配；如果还要在线程或长期任务中保存，常常需要 =Send + 'static=。

* 6. 选择建议

| 需求 | 推荐形式 |
|---|---|
| 临时调用，编译器应内联 | =F: Fn(...)= / =impl Fn(...)= |
| 闭包需要修改状态 | =F: FnMut(...)= |
| 闭包消费自身状态 | =F: FnOnce(...)= |
| 多个不同闭包放进集合 | =Box<dyn Fn(...)>= |
| C API 或只允许代码地址 | 不捕获的闭包转 =fn(...)= |
| 需要访问或序列化状态 | 用结构体保存状态，闭包只负责行为 |
