* Redis Cluster → PostgreSQL write-behind

Rust uses redis-rs ClusterClient/ClusterConnection and SQLx PgPool. PostgreSQL can
be a local standalone container or a CloudNativePG cluster's read/write Service.
No special CloudNativePG client driver is required.

** Local development

Requires Docker with Compose v2, native Redis 7+ binaries (redis-server and
redis-cli), and Rust. Native Redis processes avoid Docker Desktop's cluster
advertised-address/NAT problem. All six nodes bind to loopback only.

#+begin_src shell
# Preserve your old .env before replacing it.
cp .env.example .env
bash scripts/start-postgres.sh
bash scripts/redis-cluster.sh start
bash run.sh
#+end_src

The application runs the SQL migrations automatically. The existing .env's
REDIS_URL is no longer used: set REDIS_CLUSTER_NODES to comma-separated seed URLs.
Every node address advertised by the cluster must be reachable by the application.
Use rediss:// URLs for TLS-enabled Redis clusters.

The local PostgreSQL password is deliberately development-only. If POSTGRES_PORT
or POSTGRES_PASSWORD is changed, update DATABASE_URL to match (URL-encode special
characters). Existing Docker volumes retain their original database/password;
changing environment variables does not update an initialized database.

The Redis script is restartable, retains AOF data, and refuses to operate on an
unrelated Redis instance. It creates three primaries and three replicas only when
all nodes have an uninitialized topology. It never resets an existing cluster.
Readiness also waits for every primary to have an online, sufficiently caught-up
replica so min-replicas-to-write does not reject the first application write.
Ports 7000–7005 and bus ports 17000–17005 must be available.

#+begin_src shell
bash scripts/redis-cluster.sh status
bash scripts/redis-cluster.sh stop
docker compose stop postgres
#+end_src

REDIS_CLUSTER_BASE_PORT and REDIS_CLUSTER_DIR override the Redis script's base
port/data directory. Use the same values for start/status/stop and update the
application's seed URLs accordingly. No stop command deletes persisted data.

** CloudNativePG

Requires an existing Kubernetes context, a running CloudNativePG operator whose
CRD supports spec.postgresql.synchronous, and a default StorageClass. This script
does not install or upgrade the operator, Redis, or the application.

#+begin_src shell
bash scripts/deploy-cnpg.sh
#+end_src

NAMESPACE defaults to redis-cache-example. The manifest creates app-db with three
instances, database dbname, owner app, and 10Gi per instance. It requires one
synchronous standby before committing writes; writes pause if none is available.
Credentials are generated by the operator in Secret app-db-app, not hardcoded.

Applications running inside this Kubernetes cluster should set DATABASE_URL to
the Secret's uri (or construct it from username/password/host/dbname), targeting:

#+begin_example
app-db-rw.redis-cache-example.svc.cluster.local:5432
#+end_example

Use the rw Service, not a Pod IP or the ro Service. SQLx validates pooled
connections before acquisition, and failed events stay pending for retry when
the primary changes. For verified TLS, mount the CNPG CA Secret app-db-ca and set
sslmode=verify-full&sslrootcert=/path/to/ca.crt in DATABASE_URL. Do not put real
credentials into version control. Both PG and Redis addresses must be reachable
from the application; the loopback Redis development cluster is not accessible
from Kubernetes Pods. Production Redis needs its own externally managed cluster.

For local debugging only, kubectl port-forward svc/app-db-rw 5432:5432 -n
redis-cache-example can expose PostgreSQL. That session may need restarting after
a primary change and is not a production failover solution.

** Write and recovery semantics

- A same-slot Lua script appends the full user snapshot to ={users}:outbox= and
  updates ={users}:cache:<id>= with a 300-second TTL. The outbox has no TTL and
  is not trimmed before acknowledgment. No KEYS/SCAN or cache deletion is needed.
- XREADGROUP distributes events among workers in the fixed =postgres-writers=
  group; XAUTOCLAIM recovers events pending for 30 seconds, including after crashes.
- PostgreSQL uses one atomic INSERT ... ON CONFLICT statement. The stream ID's
  numeric (milliseconds, sequence) tuple is saved with each user, preventing an
  older/replayed event from overwriting a newer update when workers race.
- Only after the SQL statement commits does a Lua script XACK and XDEL the event.
  A crash between SQL commit and ACK causes a harmless replay. This is at-least-once
  delivery with idempotent database updates, not a distributed transaction.
- Redis connection errors reconnect with capped exponential backoff. SQL errors,
  including initial database unavailability, are retried. Other SQL errors,
  invalid messages, and unique-email conflicts are logged and left pending rather
  than silently discarded. Add operational alerting for pending/backlog growth;
  this example does not implement a dead-letter queue.
- Ctrl+C/SIGTERM stops the worker without discarding pending events. Set
  WRITE_DEMO_USER=false for worker-only processes; the default queues user 1 at
  startup to demonstrate the write path.

** Limits

The single ={users}= hash tag deliberately keeps the cache/outbox Lua operations
in one cluster slot. It demonstrates Cluster routing/failover, not distributed
write throughput. Sharding needs one ordered outbox per partition and an explicit
partition identity in PostgreSQL's version model. Only one consumer group owns
this outbox: XDEL would otherwise remove entries still needed by other groups.

Redis AOF uses appendfsync always, noeviction, and min-replicas-to-write=1 locally.
Redis Cluster replication is still asynchronous: accepted writes can be lost in
some failures. This is not an absolute no-data-loss guarantee. Production requires
durability policy, backups, failure-domain placement, TLS/ACLs, capacity monitoring,
and controlled failover validation. Do not flush/recreate the stream while keeping
PG versions without coordinating recovery; retain the stream's monotonic ID history.

The old =user:*= cache keys are not migrated automatically. Drain the old worker
before upgrading; new writes use only the new cache/outbox namespace. Database
version checks apply only to this stream; independent writers must share its
ordering contract. User IDs are application-assigned in this example.
