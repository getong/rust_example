# MAI-UI Studio · GPUI × Ollama

将 `../gpui_video_example` 的 GPUI 桌面交互方式，与 `mai_ui_video_player` 的 Ollama → HTML/CSS 设计流程结合，做成不限于播放器的通用界面设计工作台。GPUI 提供原生编辑器、进度和历史管理，Wry WebView 在同一个窗口中渲染文档；不是把模型作为 GPUI 控件库，也不是生成可执行的 Rust 代码。另提供「截图定位」模式，将本地 Python MAI-UI 项目中 `MAIGroundingAgent` 的截图 + 指令 → 坐标预测流程用 Rust 实现。

## 启动

确保本地 Ollama 已启动、已经安装需要的模型，然后在工作区运行：

```bash
ollama serve
ollama pull Maternion/mai-ui:8b
cargo run -p gpui_mai_ui_client
```

如果 Ollama 已运行，不需要再次执行 `ollama serve`。默认接口为 `http://localhost:11434/v1/chat/completions`，默认最大输出 16384 tokens；窗口中可修改接口、模型和输出上限。其他服务需支持 OpenAI chat completions SSE（`data:`、`delta.content`、`finish_reason` 和 `[DONE]`）。MAI-UI 的主要用途是截图理解和 GUI 操作，并非 HTML 生成；建议在「界面设计」中选择擅长代码生成的模型，在「截图定位」中选择支持图片输入的 MAI-UI 视觉模型。两个模式的设置分别保存，互不覆盖。

原生内嵌预览支持 macOS / Windows，Windows 需要 WebView2 Runtime。其他桌面平台保留生成、源码和导出功能，暂未接入 GTK WebView。首次编译需要下载 GPUI、WebView 等依赖。

原生预览与 GPUI 输入框分别拥有系统焦点。进入编辑器（包括从预览返回、Tab 切换和切换到源码）时，会把系统输入响应者交回 GPUI，保证中文等输入法的组合输入发送到正确控件；不会在预览每次重绘时强行抢回焦点。

## 使用流程

1. 在提示词中描述任意界面：播放器、旅行规划、设置页等，点击「生成 / 继续修改」。
2. 进度实时显示连接/模型加载、等待首个输出、思考和 HTML 生成阶段，以及耗时和接收字符数。总 token 数无法预知，因此不伪造百分比；服务返回 usage 时会显示最终输出 tokens。
3. HTML/CSS 逐步到达后，在样式闭合且出现 body 时开始预览，每约 900ms 更新一次；「查看源码」可以检查当前原始流。流式页面可能不完整，只有完整并正常结束的输出才会形成稳定版本。
4. 在同一个编辑框继续输入修改意见，再次生成时会把当前版本的祖先提示词和完整文档作为上下文。提示词不会自动清空，可反复修改或重新提交；使用完整祖先上下文会消耗模型上下文窗口，过长时可切换「空白基线 / 新方向」。
5. 「保存提示词」收藏当前文本；成功生成所用的提示词也自动加入提示词库。点击库中的条目即可复用到编辑框。
6. 「回退一步」切换到当前版本的父版本；历史列表也可直接选择任意版本。从旧版本继续生成会创建新分支，原来的后续版本不会删除。编辑框保留当前修改意见，不随基线切换而清空。
7. 「下载 HTML」通过原生保存对话框导出当前稳定版本的离线 HTML，保留沙箱和资源限制；浏览器直接打开即可查看。不依赖 Ollama，不会导出尚未完成的流。

取消、网络错误、模型错误、输出截断、格式错误均不会覆盖当前稳定版本，预览会恢复到生成前的基线；原始失败输出可在源码中检查，提示词保留，可修改后重试。取消也会中止网络请求；关闭窗口会取消当前任务。

## 截图定位（第 6 项）

参考 `/Users/gerald/test/python/MAI-UI/MAI-UI/src/mai_grounding_agent.py` 的消息结构、`<answer>` 响应协议与 999 坐标缩放规则，原生实现，不需要 Python 运行环境。

1. 顶部切换到「截图定位」，配置支持视觉输入的 OpenAI 兼容流式接口和模型。
2. 点击「导入截图」，选择 PNG / JPEG；在指令框输入要寻找的元素，例如「定位右上角的设置按钮」。截图会发送到所配置的模型接口，请勿导入敏感内容。
3. 点击「定位元素」，实时显示连接、模型输出和思考字符计数，可取消；「原始响应」查看当前流。模型需返回 `<answer>{"coordinate":[x,y]}</answer>`，坐标范围为 0–999，可带 `<grounding_think>` 视觉说明。
4. 完整响应通过校验后，在原截图上显示红色标记，同时显示归一化坐标、原图像素坐标和 token 用量。缩放预览保持标记相对位置；边缘坐标映射到最后一个有效像素。
5. 点击历史记录恢复当时的截图、指令和定位结果，可继续修改指令；失败、未找到目标、取消或输出截断不会替换已有结果。「导出标注 HTML」保存包含截图和定位标记的离线页面。

截图会真实解码后重新编码，不信任扩展名；输入最多 8 MiB、1600 万像素、单边 8192 像素。优先用 PNG，超过 1 MiB 时改用 JPEG；仍超过 1 MiB 则拒绝导入并提示缩小截图，不偷偷改变尺寸或坐标空间。截图与定位历史保存在会话旁的 `.grounding.json` 文件（例如 `session.grounding.json`），相同截图去重。再次启动会恢复截图与选中结果；请注意本地文件包含截图内容。

这是参考项目 **grounding 子流程** 的移植，不是完整移动设备导航代理：不自动截取屏幕、不点击真实设备、不调用 ADB/MCP，也不执行模型输出的系统操作。截图定位结果不反向修改 HTML；HTML 设计历史与定位历史相互独立。生成任务或文件对话框进行中禁止切换模式。

## 持久化与配置

默认把设置、草稿、提示词库、版本文档、父版本关系和当前选择保存在本包的 `studio-output/session.json`（已加入 gitignore）。成功生成、切换版本、保存/复用提示词和正常关闭时自动保存；写入临时文件并同步后替换旧文件。保存失败会在窗口中报错，内存中的结果仍可导出；关闭时保存失败会阻止关闭，以免静默丢失数据。损坏的历史文件会阻止启动，不会被空会话覆盖。

可使用环境变量：

```bash
MAI_UI_ENDPOINT=http://localhost:11434/v1/chat/completions \
MAI_UI_MODEL=Maternion/mai-ui:8b \
MAI_UI_SESSION=/absolute/path/my-design.json \
cargo run -p gpui_mai_ui_client
```

兼容服务如需鉴权，设置 `MAI_UI_API_KEY`；只从环境读取，不写入会话。接口与模型环境变量会覆盖启动时加载的配置。不要让多个实例同时写同一个会话文件；不同项目使用不同 `MAI_UI_SESSION`。

## 安全与边界

「界面设计」生成的是视觉原型，不是可运行的业务应用，也不实现真实的视频解码或播放器功能。两个模式的预览均放在不授予脚本、表单提交、弹窗和顶层导航权限的 iframe 沙箱内，内层 CSP 默认禁止脚本与外部资源；原生 WebView 额外拒绝外部导航、弹窗和下载。导出也使用相同的 iframe/CSP 包装。宿主页面只包含本应用生成的静态包装，模型文档经转义后写入 srcdoc，不直接拼接到宿主 DOM。为兼容 WebKit 的 srcdoc 渲染，不使用 WebView 的全局 JavaScript 关闭开关，而是由沙箱和 CSP 禁止模型页面脚本。该包装不是通用 HTML 清洗器；仅使用可信服务输出，不把导出的页面部署到包含敏感信息的站点。

连接超时 30 秒，单次生成最长 2 小时，HTML 输出限制 4 MiB。完成性检查拒绝缺少闭合标签的输出，但不等于完整 HTML 语法/视觉验证；不同模型仍可能生成不理想的页面。达到输出上限时不会拼接残缺页面或自动覆盖历史，请增加上限或精简需求后重试。

## 检查

```bash
cargo test -p gpui_mai_ui_client --no-default-features
cargo check -p gpui_mai_ui_client
cargo fmt -p gpui_mai_ui_client -- --check
```

核心测试不需要显示服务器或 Ollama，覆盖分支上下文、版本回退、提示词去重、会话持久化、UTF-8/SSE 分片、流式思考计数、token 用量、错误和截断、预览沙箱，以及截图校验、多模态请求、坐标解析和映射、定位历史恢复与损坏检测；本地模拟 HTTP 服务还验证鉴权、HTML / 定位流式传输、HTTP 错误和卡住请求的取消，需要允许绑定回环端口。GUI 需要实际启动窗口检查；真实模型生成与截图定位效果需要本地 Ollama 服务和相应模型。
