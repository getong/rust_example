# ML-KEM 文件加密 demo

使用 aws-lc-rs：ML-KEM-1024 封装共享秘密，经 HKDF-SHA256 派生 AES-256-GCM 密钥。
每次加密重新封装，并生成随机盐和 nonce。保留 `src/encrypt.rs`、`src/decrypt.rs`、`src/common.rs` 三个源文件。

```sh
# 接收方生成密钥对，只需要生成一次；stdin 输入密码，直接 Enter 则不设密码
cargo run --bin decrypt -- --keygen recipient.public recipient.private

# 加密端使用接收方公钥；公钥有密码时提示输入密码；input.txt 是自己准备的文件
cargo run --bin encrypt -- recipient.public input.txt encrypted.bin

# 接收方使用私钥解密；有密码时输入生成密钥对时设置的同一密码
cargo run --bin decrypt -- recipient.private encrypted.bin recovered.txt

cargo test -p encrypt_file
```

生成时从 stdin 读取一行密码，只去掉行尾换行，保留空格；直接 Enter 表示无密码。stdin 提前关闭会报错，不会默认为无密码。终端输入密码时每个字符显示为 `*`，支持退格修改，Ctrl+C / Ctrl+D 取消输入；生成、加密和解密均使用此输入方式。管道或重定向输入仍按行读取，不回显密码。

无密码公私钥保持 aws-lc-rs ML-KEM-1024 原始二进制格式：公钥 1568 字节，私钥 3168 字节，兼容此前生成的密钥，使用时不读取密码。
设置密码后，公私钥均使用同一密码分别加密保存；加密和解密各自自动提示输入密码，密码错误时不创建输出文件。私钥必须独立保管、备份，不能随密文公开；Unix 创建权限为 0600，其他平台需配置访问权限。
公钥可以公开；受密码保护的公钥需要向加密端提供密码。加密端必须通过可信渠道确认公钥归属。此方案不提供发送方身份认证或数字签名。

所有输出均使用排他创建，拒绝覆盖现有文件。只有完整认证通过后才写入解密文件。
密钥生成先写私钥再写公钥；若第二次写入失败，已写入的私钥会保留，需要检查报错并使用新的路径重新生成配对密钥。
发生磁盘写入错误时，可能留下不完整输出；程序不会自动删除或覆盖这些文件。

## v1 文件格式

| 字段 | 字节数 |
| --- | ---: |
| 魔数 `ALCFENC\0` | 8 |
| 版本 `1` | 1 |
| 算法套件 `1`（ML-KEM-1024 / HKDF-SHA256 / AES-256-GCM） | 1 |
| HKDF 随机盐 | 32 |
| ML-KEM 封装密文 | 1568 |
| AES-GCM nonce | 12 |
| 文件密文 | 与明文等长 |
| GCM 认证标签 | 16 |

前 1622 字节全部作为 GCM AAD 认证。HKDF info 固定为
`encrypt_file/v1/ML-KEM-1024/HKDF-SHA256/AES-256-GCM`，输出 32 字节密钥。
文件不保存私钥、共享秘密或 AES 密钥。旧的口令加密 demo 文件不兼容此格式。

这是自定义文件格式的学习示例，当前整文件读入内存，适用于小文件，不是经过审计的生产文件加密协议。

## 密码保护的密钥格式 v1

头部为 `ALCFKEY\0`（8 字节）、版本 `1`、套件 `1`、密钥类型（公钥 `0` / 私钥 `1`）、32 字节随机盐、12 字节随机 nonce；随后为加密的原始密钥及 16 字节 GCM 标签。
使用 PBKDF2-HMAC-SHA256（600,000 次迭代）派生 32 字节 AES-256-GCM 密钥，整个 55 字节头部作为 AAD。公私钥分别生成独立随机盐和 nonce，文件不保存密码。加密数据文件仍使用原有 v1 格式。
