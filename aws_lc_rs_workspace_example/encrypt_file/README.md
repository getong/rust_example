# ML-KEM 文件加密 demo

使用 aws-lc-rs：ML-KEM-1024 封装共享秘密，经 HKDF-SHA256 派生 AES-256-GCM 密钥。
每次加密重新封装，并生成随机盐和 nonce。公共逻辑位于 `src/lib.rs`，两个 bin 只处理命令行参数。

```sh
# 接收方生成密钥对，只需要生成一次；stdin 输入密码，直接 Enter 则不设密码
cargo run --bin decrypt -- --keygen recipient.public recipient.private

# 加密端使用接收方公钥；有密码时输入生成密钥对时设置的同一密码；input.txt 是自己准备的文件
cargo run --bin encrypt -- recipient.public input.txt encrypted.bin

# 接收方使用私钥解密；有密码时输入生成密钥对时设置的同一密码
cargo run --bin decrypt -- recipient.private encrypted.bin recovered.txt

cargo test -p encrypt_file
```

生成时从 stdin 读取密码，非空密码必须再输入一次确认；只去掉行尾换行，保留空格；直接 Enter 表示无密码。stdin 提前关闭会报错，不会默认为无密码。终端密码输入由 `inquire::Password` 处理，使用 `Masked` 模式显示 `*`，支持退格修改和取消输入；生成、加密和解密使用此输入方式。密码最多 1024 字节（终端输入提交时检查，管道输入上限包含换行）。管道或重定向输入仍按行读取，不回显密码。

无密码公私钥保持 aws-lc-rs ML-KEM-1024 原始二进制格式：公钥 1568 字节，私钥 3168 字节，兼容此前生成的密钥，使用时不读取密码。
设置密码后，公钥和私钥均使用同一密码加密保存，各自使用独立随机盐和 nonce；加密、解密时都会提示输入密码，密码错误时不创建输出文件。私钥必须独立保管、备份，不能随密文公开；Unix 创建权限为 0600，Windows 创建时使用仅所有者可访问且禁止继承的 DACL（需支持 ACL 的文件系统）。
公钥文件可以分发给加密端，使用受保护公钥时还需提供密码。旧版生成的裸公钥不含密码信息，更新程序不会自动使其需要密码；如需此行为，请用新的文件名重新生成带密码的密钥对，并保留旧私钥以解密旧文件。旧 v1 密码保护公钥仍不接受。加密端必须通过可信渠道确认公钥归属。此方案不提供发送方身份认证或数字签名。

所有输出均使用排他创建，拒绝覆盖现有文件；同步文件内容后，Unix 还同步父目录。只有完整认证通过后才写入解密文件。
密钥生成先写私钥再写公钥；若第二次写入失败，已写入的私钥会保留，需要检查报错并使用新的路径重新生成配对密钥。
发生磁盘写入错误时，可能留下不完整输出；程序不会自动删除或覆盖这些文件。

## v1 文件格式

| 字段 | 字节数 |
| --- | ---: |
| 魔数 `ALCFENC\0` | 8 |
| 版本 `1` | 1 |
| 算法套件 `1`（ML-KEM-1024 / HKDF-SHA256 / AES-256-GCM） | 1 |
| HKDF 随机盐 | 32 |
| ML-KEM 封装密文 | 1568 |
| AES-GCM nonce | 12 |
| 文件密文 | 与明文等长 |
| GCM 认证标签 | 16 |

前 1622 字节全部作为 GCM AAD 认证。HKDF info 固定为
`encrypt_file/v1/ML-KEM-1024/HKDF-SHA256/AES-256-GCM`，输出 32 字节密钥。
文件不保存私钥、共享秘密或 AES 密钥。旧的口令加密 demo 文件不兼容此格式。

这是自定义文件格式的学习示例，采用有界整文件读取，明文上限 64 MiB（密文额外允许头部和标签），拒绝非普通文件及读取时增长的文件；加密原地处理并分段写入头部/密文，避免额外复制整个文件，不是经过审计的生产文件加密协议。

## 密码保护的密钥格式 v2

头部为 `ALCFKEY\0`（8 字节）、版本 `2`、套件 `1`、密钥类型（公钥 `0`、私钥 `1`），然后是三个小端 u32 参数：内存 KiB、迭代数、并行度；随后为 32 字节随机盐、12 字节随机 nonce、加密密钥和 16 字节 GCM 标签。整个 67 字节头部作为 AAD。

新公私钥使用 Argon2id v0x13（64 MiB、t=3、p=1）派生 32 字节 AES-256-GCM 密钥。读取支持内存 64–256 MiB、t=3–10、p=1–4，超范围参数在执行 KDF 前拒绝，避免恶意资源消耗。以后调参无需改变格式版本；更换 KDF 或布局必须另定义版本。

旧 v1 PBKDF2-HMAC-SHA256 私钥仍可读取；其 600,000 次迭代是固定格式约定，不可直接修改。新代码不写 v1。原始无密码密钥和 v1 数据文件保持兼容，HKDF-SHA256 不变。

读取完成后的密码、派生密钥字节、原始私钥缓冲区、明文缓冲区及 Argon2 工作内存使用 `Zeroizing` 自动擦除。此措施不覆盖 `inquire` 内部输入缓冲区，也不保证清除操作系统交换区、崩溃转储或终端外部副本。Argon2id 刻意增加口令派生成本，不能视为 KDF 加速；没有声称未经基准验证的抗攻击倍数。

不提供发送方签名、多接收方封装或自动密钥轮换。Windows 权限代码需要在 Windows 主机验证；当前 macOS 测试不能证明 Windows ACL 行为。


## 性能测量

macOS 下运行 `python3 tools/benchmark.py`，分别构建 debug/release，在临时目录对带密码和无密码的密钥生成、4 B / 1 MiB / 64 MiB 文件加解密各测量 3 次，并校验解密结果。不会读取或覆盖现有密钥及文件。原始耗时、CPU 时间、峰值 RSS 和分阶段计时保存为 `benchmarks/results.json`。编译时间与运行时间分开；密码由管道输入，不包含手工输入等待。测试包含磁盘同步和敏感缓冲区擦除。

可使用 `--runs 5 --sizes 4 1048576 --profiles release --output /tmp/results.json` 调整样本。`--skip-build` 要求目标二进制已经带 `perf-trace` feature 构建。首次运行需要编译依赖；debug 的密码派生和大缓冲区擦除较慢，完整测量需要数分钟。

`perf-trace` 默认关闭。需要诊断单次命令时，可运行 `cargo run --release --features perf-trace --bin encrypt -- <公钥> <输入> <新输出>`，stderr 输出 `BENCH`、阶段名和纳秒数，不记录密码或密钥内容。父阶段包含子阶段，不能将所有行直接相加；同名阶段在一次命令中可能出现多次（例如 keygen 有两次密码派生）。手动运行时 `password.input` 会包含输入等待，自动 benchmark 则不会。

本机测量结果及解释见 [benchmarks/REPORT.md](benchmarks/REPORT.md)。
