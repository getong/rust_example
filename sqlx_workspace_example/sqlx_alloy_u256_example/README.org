* SQLx + Alloy U256 + PostgreSQL BYTEA 大数比较示例

这个用例演示：直接使用 =alloy_primitives::U256= 和它的 =sqlx= feature，
把完整的 Ethereum =uint256= 存入 PostgreSQL，并在 SQL 的 =WHERE= 和
=ORDER BY= 中比较数值大小。

** 为什么使用 BYTEA

=alloy-primitives= 的 =sqlx= feature 复用了 =ruint= 的 SQLx 实现：

- =U256= 固定编码为 32 字节；
- 编码采用大端序，最高有效字节在前；
- SQLx 将它映射到 PostgreSQL =BYTEA=；
- 迁移通过 =octet_length(amount) = 32= 强制所有值等长。

对于等长的大端序无符号整数，字节字典序与整数大小顺序一致。因此下面的 SQL
虽然比较的是 =BYTEA=，结果与比较 =U256= 的数值大小相同：

#+begin_src sql
SELECT label, amount
FROM u256_values
WHERE amount > $1
ORDER BY amount;
#+end_src

=amount= 上建立了 B-tree 索引，可以支持等值、范围和排序查询。

这种方案适合存取、比较和排序，但 =BYTEA= 不是 PostgreSQL 数值类型，不能直接执行
=amount + 1=、=SUM(amount)= 等数值运算。如果需要在 SQL 中进行算术，应改用
=NUMERIC(78, 0)=，并在 Rust/SQL 边界转换 =U256=。

** SQLx 版本说明

当前 =alloy-primitives 1.7.1= 的 =sqlx= feature 依赖 SQLx 0.8，因此本示例固定使用
=sqlx 0.8.6=。如果同时使用 SQLx 0.9，两个版本的 =Type=/=Encode=/=Decode=
trait 不相同，=U256= 不能直接绑定到 SQLx 0.9 查询。

** running postgresql docker

#+begin_src shell
docker run \
  --name my_postgres \
  -e POSTGRES_PASSWORD=PgSuper2026! \
  -d \
  -p 5432:5432 \
  postgres:18.3
#+end_src

配置数据库连接：

#+begin_src shell
export DATABASE_URL='postgres://postgres:PgSuper2026!@localhost:5432/sqlx_alloy_u256_example'
sqlx database create
#+end_src

程序会通过 =sqlx::migrate!()= 自动执行 migrations，然后幂等写入五个 U256 样例：

#+begin_src shell
cargo run -p sqlx_alloy_u256_example
#+end_src

阈值是 =2^128=。预期 SQL 查询只返回 =above_threshold= 和 =u256_max=：

#+begin_example
SQL threshold: 340282366920938463463374607431768211456
Values greater than the threshold (compared by PostgreSQL):
  above_threshold = 340282366920938463463374607431768211457
  u256_max = 115792089237316195423570985008687907853269984665640564039457584007913129639935
#+end_example

清理数据库：

#+begin_src shell
sqlx database drop
#+end_src
